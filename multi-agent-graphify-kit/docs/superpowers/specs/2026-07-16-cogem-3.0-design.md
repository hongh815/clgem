# Cogem 3.0 Governance Hardening Design

## Objective

Create a portable five-role multi-agent coordination kit that makes Skill authoring, dispatch authorization, graph freshness, and independent review evidence deterministic rather than policy-only.

## Permanent roles

Plan A contains Coordinator, Graph Analyst, Worker A, Worker B, and Independent Reviewer. At most two source-writing tasks run concurrently. High-risk work adds a second fresh execution of the same Independent Reviewer role, not a sixth permanent role.

## State and bootstrap

The portable release has empty live-state directories, no generated graph, and an explicit bootstrap `Comm.md`. The Coordinator may create initial coordination records and generated artifacts without a task, but this exception cannot modify source files.

## Skill policy

Every immediate `skills/*` directory follows one generic contract: required `SKILL.md` and `manifest.txt`, matching lowercase-hyphen name, a `Use when` activation description, allowed responsibility directories, manifest completeness, and valid schema JSON. The manifest is authoritative during packaging.

## Graph and dispatch

The graph contains an input fingerprint over non-volatile graph inputs. Dispatch is a separate gate from structural validation. A task is dispatchable only when assigned, scoped, leased, dependency-complete, role-authorized, project-valid, and backed by a fresh graph.

## Review evidence

The Coordinator computes a deterministic review tree hash and stores it in task `review_tree_hash`. Standard and adversarial reports bind their session and permission proof to that hash. Approved and integrated tasks must still match the current tree; closed historical tasks remain valid against their task-bound review hash after later work changes the repository.

## Portability

Python 3.11+ standard library only. Commands are non-interactive, outputs deterministic, provider credentials external, and the ZIP excludes generated/transient state.
