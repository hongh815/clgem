# Cogem 4.0 Skill Governance and Scope Enforcement Design

## Objective

Turn Skill criticality and task scope from documented expectations into executable gates. Cogem 4.0 must force every task that writes under `skills/` to use high-risk review, support the Codex-compatible Skill root layout, validate an exact two-field frontmatter contract, record a dispatch-time file snapshot, verify actual changes before handoff or review, and initialize new Skills non-interactively.

## Task risk classification

A shared path predicate normalizes `/` and `\\`, treats a path as under a root when its normalized components start with the root components, and classifies a task as Skill-touching when any `write_set` entry is `skills` or lies below it. `dispatch-check` and `validate` use the same predicate and emit `SKILL_REVIEW_LEVEL_REQUIRED` when a Skill-touching task does not declare `review_level: high-risk`. `review_level` is required in every task contract.

## Skill file contract

Each `skills/<name>/` directory permits exactly `SKILL.md`, `manifest.txt`, and the optional directories `agents/`, `assets/`, `references/`, `scripts/`, `schemas/`, and `tests/`. Names are 1–63 characters and use lowercase alphanumeric hyphen-separated tokens. `SKILL.md` frontmatter contains exactly `name` and `description`; both are single-line scalar values, the name matches the directory, and the description starts with `Use when`.

## Scope evidence

A successful CLI `dispatch-check` creates an immutable baseline snapshot at `.agents/snapshots/<TASK-ID>.json`. The snapshot records the task identity, lease, declared write scope, baseline file hashes, and graph fingerprint. Re-running dispatch for the same contract preserves the baseline; a changed lease or write scope is rejected instead of silently resetting it.

`scope-check` compares the current project tree with that baseline and reports created, modified, and deleted files. Every changed path must fall under a declared `write_set` path. Any Skill change must be high-risk, and changing Skill content requires the corresponding `manifest.txt` to change in the same task. The result is persisted with a reviewable-tree hash. Handoff and review-ready or completed states require passing scope evidence; active pre-review states remain checkable without blocking incremental implementation.

## Skill initialization

`cogem skill-init <name>` creates `SKILL.md`, `manifest.txt`, and `agents/openai.yaml`. `--resources` accepts a comma-separated subset of `references`, `scripts`, `assets`, `schemas`, and `tests`; `schemes` is accepted as an alias for `schemas`. Creation rejects invalid or conflicting names, runs the same Skill validation immediately, and removes the new directory if validation fails.

## Portability and release

The implementation uses Python 3.11+ standard library only. All commands are non-interactive and JSON-friendly. Live task, snapshot, graph, report, and handoff records are removed from the portable release. Version 4.0.0 is a breaking release because task contracts now require `review_level`.
